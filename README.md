# 구현 기획안

처음 만난 사람들이 상황에 맞는 게임으로 서로를 알아가고, 그 결과가 성향 리포트와 캐릭터로 남는 웹 서비스.
그 축 · 유형 · 게임 · 리포트 전체 명세다.

## 파일

| 파일 | 용도 |
|---|---|
| **[구현기획안.md](구현기획안.md)** | 본문. **AI 에이전트에 넣는 건 이 파일이다** |

`.html`은 GitHub에서 바로 렌더되지 않는다. 내려받아서 브라우저로 열면 된다.

## AI 에이전트에 넣을 때

`구현기획안.md`를 통째로 넣되, **`§0 읽는 법 — 용어부터 맞춘다`를 반드시 포함한다.**
용어가 어긋나면 나머지가 전부 어긋난다. 특히 이 세 가지를 에이전트가 헷갈린다.

- **축 개수** — 시스템 전체 정의는 18개지만, 한 사람이 한 세션에서 갖는 축은 9개다
- **유형과 칭호의 차이** — 유형은 절대값(나 혼자 정해짐), 칭호는 팀 내 순위(팀 바뀌면 바뀜)
- **`IMPRESSION` 출처** — 유형 결정에 절대 안 쓴다. 레이더 점선과 인식 격차 전용

## 문서 구조

```
§0  용어              9개 용어 고정
§1  결정 로그          D1~D16
§2  카테고리           2단 구조 — 단체(팀플·합석) / 연인(낮·밤)
§3  축 체계            18축 · 카테고리별 라벨 · 데이터 모델 · 출처별 용도
§4  유형              32종 전문 — 이름 · 대사 · 강점 한 줄
§5  칭호              단체 9종 + 연인 10종
§6  궁합              계산식 · 등급 컷 · 9축 × 4카테고리 가중치 표
§7  문항              설계 원칙 6개 · 팀플 18문항 확정 · 나머지 초안
§8  게임              Stage 인터페이스 · 프레임 2벌 · 오프라인 카탈로그
§9  리포트            5층 구조 · 사전 스키마 · LLM 계약
§10 MVP 화면          11단계 흐름 + 시각 예시
§11 담당 · 예외 · 미결
```

## 파트별로 어디부터 보면 되나

| 파트 | 담당 | 먼저 볼 절 |
|---|---|---|
| 아이스브레이킹 | 진웅 · 재환 | §8 게임 · §7 문항 |
| 게임 | 치영 · 민우 | §8-1 Stage 인터페이스 · §3-4 데이터 모델 · §6 궁합 |
| 기획 | 종훈 · 기준 | §3 축 · §4 유형 · §9 리포트 |

각 파트 산출물은 §11에 정리돼 있다.

## 상태

**초안 v1.** 미결 9건은 §16에 있다.
그중 **O2(캐릭터 일러스트 32종)** 와 **O7(서비스 이름)** 은 공유 카드 구현 전에 정해져야 한다.

구현 순서는 **팀플 하나를 수직으로 완성한 뒤 나머지를 수평 확장**하는 것으로 잡혀 있다 (§17).
