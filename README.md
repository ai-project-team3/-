# 얼음땡

처음 만난 다섯 명이 18분짜리 아이스브레이킹을 함께 하면, 각자의 캐릭터 카드와
팀 리포트가 나오는 웹 서비스. 이 저장소는 그 기획 문서를 담는다.

`.html`은 GitHub에서 바로 렌더되지 않는다. 내려받아 브라우저로 열면 된다.

**두 문서가 충돌하면 `얼음땡-기획안.md`가 우선한다.** 구현기획안은 팀 프로젝트
외 카테고리와 확장 설계를 담고 있어서, 이번 판에서 쓰지 않는 내용이 섞여 있다.

## AI 에이전트에 넣을 때

`얼음땡-기획안.md`를 통째로 넣는다. 에이전트가 자주 헷갈리는 네 가지를 미리 못박아 둔다.

- **MBTI는 능력치와 유형 판정에 관여하지 않는다.** 리포트 문장을 쓸 때 컨텍스트로만
  들어가고, 화면에 언급되는 곳은 개인 카드 헤더 한 곳뿐이다
- **첫인상 투표는 능력치 본값이 아니다.** 레이더의 점선과 인상 변화 전용이다.
  두 번(게임 전·후) 받으며, 유형 판정에 절대 섞지 않는다
- **유형은 절대 평가, 칭호는 상대 평가다.** 유형은 본인 기록만으로 정해지고,
  칭호는 팀 안에서의 순위라 팀이 바뀌면 바뀐다
- **등급과 궁합은 바닥이 정해져 있다.** 팀 등급의 최하가 `S`, 궁합의 최하가 `B`다.
  나쁜 결과가 나오지 않는 것이 의도이지 버그가 아니다

## 파트별로 어디부터 보면 되나

| 파트 | 먼저 볼 절 |
|---|---|
| 뼈대 | §4 진행 구성 · §13 데이터 모델 · §14 화면 목록 |
| 리포트 | §5 능력치 · §6 유형 · §8 궁합 · §9 팀 등급 · §10 결과 화면 |
| 기획 | §4 문항 전문 · §11 문구 규칙 · §17 확정이 필요한 것 |

두 팀이 서로를 기다리지 않으려면 **§15의 계약 JSON을 먼저 맞춘다.** 리포트 쪽은
그 JSON을 임시 값으로 채워두면 뼈대가 나오기 전에도 작업을 시작할 수 있다.
